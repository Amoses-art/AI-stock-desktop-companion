## 一、总体结论

**债务比规划预估的窄，但缺陷比预估的深。**

- 好消息：`trading_hours_guard`（chinese_calendar 节假日）、`alert_engine`（3% 骤变默认 + UTC 冷却 + 轮询绑定）、`skill_orchestrator + analysis_engine`（统一编排雏形）、`multi_market_router + adapters`（数据源抽象）**均已存在**，PRD 核心机制有基础，重构以"收口+补缺"为主，不是从零造。
- 坏消息：发现 **1 个新的 P0 功能缺陷**（手动刷新链路断裂，见 §四 G2），且 PRD v3.1 契约表与实现存在 **4 处偏差**，其中 2 处已在 B1/B3 踩坑返工过。

### 2.2 行情调度现状 vs PRD v3.1 §2

| PRD 要求 | 现状 | 判定 |
|---|---|---|
| A股工作日 9:15-15:00 秒级轮询 | `TradingHoursGuard` 窗口 **9:20-15:00**（ADR-021），chinese_calendar + 调休 + 周末 fallback 齐备 | ⚠️ 窗口边界不符（9:20≠9:15） |
| 午休 11:30-13:00 降频至 120s | **无任何午休逻辑**，固定 10s | ❌ 缺失 |
| 非交易时段完全停止主动请求 | poll_loop 24h 循环跑；get_quote 有非交易 cache-first 拦截（L184-228，不发外部请求）但**循环与评估仍在空转**（每天 ~8000 次无效评估） | ⚠️ 半实现 |
| 窗口边界可配置（user_config） | `TradingHoursConfig` **硬编码 DEFAULT_CONFIG**，未接 user_config | ❌ 缺失 |
| 手动刷新绕过窗口 | get_quote 不区分调用来源，手动刷新同样被 cache-first 拦截，**盘后手动刷新拿到的是旧缓存** | ❌ 缺失 |
| 收盘态快照 + 下次开市 TTL | `get_next_trading_time` 已实现（供缓存 TTL） | ✅ 有基础 |
| 港美股简化常开+限频 | `global_config` 已有 cn/hk/us/fund 分市场 interval 配置项，但 poll_loop 未用 | ⚠️ 配置存在未接线 |
