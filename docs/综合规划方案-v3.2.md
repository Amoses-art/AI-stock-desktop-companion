## 一、产品全景（最终形态收敛）

### 1.1 产品分层

```
┌─────────────────────────────────────────────┐
│ L1 核心层（默认安装即用，M1 可分享）                  │
│  桌宠交互 · 持仓管理 · 阈值提醒 · 实时行情调度         │
│  外部依赖：无                                    │
├─────────────────────────────────────────────┤
│ L2 AI 层（首启向导可选启用，M2 完整版）              │
│  聊天对话 · 9 意图 Skill · NLU 兜底 · K 线增强      │
│  外部依赖：Ollama + qwen2.5（开发 7b / 分发 3b）    │
└─────────────────────────────────────────────┘
```

### 1.2 用户体验主路径（验收基准场景）

1. **安装/首启**：安装包统一 → 首启选择向导（"仅持仓管理 / 开启 AI 对话"）→ 选前者直接进核心版
2. **日常核心循环**：桌宠常驻 → 添加持仓（三市场）→ 交易时段秒级自动刷新 → 情绪随盈亏变化 → 阈值触发（气泡+系统通知+托盘红标）→ 非交易时段静止收盘态 + 手动刷新兜底
3. **可选 AI 循环**：设置端开启 → Ollama 静默安装/镜像拉模型（进度可见）→ 对话/意图 Skill → 随时关闭（只隐藏不卸载）

## 二、目标技术架构

### 2.1 三层架构与职责边界

| 层 | 技术 | 职责（做什么） | 禁止（不做什么） |
|---|---|---|---|
| 前端（多窗口） | Vue3 + Pinia + Vite | 视图渲染、状态机、热区交互、皮肤/切图、窗口控制调用 | 业务逻辑计算、直接拼 SQL 语义、绕过 core 层裸调 invoke |
| Rust 桥 | Tauri v2 | 进程管理（Python 生命周期）、窗口管理（四窗定位/吸附/z 序）、事件转发、托盘/系统通知、Ollama 静默安装 | 业务逻辑、数据加工 |
| Python 后端 | 3.10 + asyncio + SQLite | 持仓 CRUD、行情调度引擎、数据源路由（三级降级+熔断）、提醒引擎、AI 层（Ollama/Skill/NLU） | UI 概念、窗口概念 |

### 2.2 契约总线（单一事实源）

- **Invoke 命令**（前端→Rust→Python）与**事件**（Python→Rust→前端）以契约冻结表为唯一依据
- 命名统一点分式（`portfolio.list`），清除前端 LEGACY_MAP
- 变更规则：新增字段允许，删改字段禁止（需版本协商）
- **配套机制**：契约表内嵌三端校验（Python 启动自检注册方法集 / Rust 命令白名单 / 前端类型生成），CI 级防漂移

### 2.3 关键机制归属

| 机制 | 归属 | PRD 依据 |
|---|---|---|
| 行情刷新调度（交易窗口/午休降频/节假日/零请求/收盘态） | Python 调度引擎 | v3.1 §2 |
| 数据源三级降级 + 熔断（腾讯→东财/AKShare→新浪） | Python 数据源路由 | 项目记忆 |
| 手动刷新（绕过窗口，熔断仍生效） | 前端触发 → Python 单次执行 | v3.1 §2.3 |
| 阈值提醒（自定义 + 3% 骤变默认；冷却 UTC；轮询暂停→评估暂停） | Python 提醒引擎 | v3.1 §2.2 |
| Feature Flag（ai_enabled/ai_status 状态机） | Python 存储 → Rust `ai:state` 事件 → 前端 UI 门控 | v3.1 §1.3 |
| Ollama 生命周期（检测/静默安装/镜像/拉模型/进度） | Rust 执行 + Python 状态管理 | v3.1 §1.2 |
| 多窗口（pet/panel/chat/bubble 定位、翻转、吸附） | Rust windows.rs | B1 已实现 |
